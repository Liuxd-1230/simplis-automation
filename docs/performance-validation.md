# 波形读取与运行监控的性能修改

本次只修改波形读取、原生校验、v2 导出结果复用和公共运行监控。
原生 `.sxsch/.sxcmp`、v2 YAML 源文件规则、命令名称及已有结果字段继续保留。

## 修改范围

| 位置 | 原有操作 | 当前操作 |
|---|---|---|
| `vectors.py` | 先建立全部行的元组，再建立 x/y 数组，随后重新读取文件计算摘要 | 一次读取同时解析、校验并计算原有摘要；完整读取接口保留原返回字段 |
| `native_runner.py` | 为数值和时间轴检查加载完整数组，并建立额外列表 | 逐行统计点数、有限性、单调性和频率正值 |
| `experiment_runner.py` | 正常完成路径中，同一个导出文件被解析三次 | 本次运行内按实际文件路径复用解析结果；最终只更新已有清单的信任状态 |
| `watchdog.py` | 每轮分别启动进程枚举和进程状态查询 | 同一个 PowerShell 调用返回进程和状态信息 |
| `watchdog.py` | 一次模拟器状态查询执行三个 SxCommand | 一个任务内查询脚本，通过一次 SxCommand 调用执行 |
| `watchdog.py` | 每轮重复读取完整消息日志、遍历运行目录三次 | 消息错误按新增内容读取，查询回读最多 80000 字节；三项文件检查共用本轮清单 |

完整数组读取采用 `parse_show_file()`；仅统计和校验采用 `summarize_show_file()`。
`parse_show_file()` 的原返回字段保持一致，可显式选择附带统计结果。
`build_vector_manifest()` 的原调用继续有效，可复用同一阶段已读取的数据。
复用范围限于本次已完成导出后的处理过程，没有跨实验或持久数据缓存。

## 实际验证

使用 SIMetrix 8.40.0.2 / SIMPLIS 8.40.0.25254，在新目录实际执行：

- 原生 RC：导出 1001 点，末端电压与已知 RC 结果一致；原生校验只调用逐行统计。
- v2 迟滞控制：六个导出文件各解析一次，六条波形的清单与电路行为检查通过。
- v2 实测一次远程状态查询对应一次 SxCommand 调用，逐进程 PowerShell 查询次数为零。
- 原生 RC 的 Python 分配峰值：完整读取 76245 字节，逐行统计 11104 字节，约减少 85.4%。
  这是同一个实际导出文件的 `tracemalloc` 结果，涵盖 Python 内存分配；不代表整个模拟器进程内存。
- 159 项单元测试通过。新增测试使用真实导出文件，包含重复事件时间、复数 AC、末尾非有限数值、
  时间倒序、完整/逐行结果一致性、日志分段追加与截断。

实机记录位于 `outputs/performance/final02/validation.json`，原始运行和失败尝试继续保留。
本轮使用小型真实电路核对接口与实际调用次数，没有执行 1.18 GB 文件或低配硬件基准测试。

## 监控取舍与已确认限制

正常响应时，详细窗口扫描间隔为 10 秒；发现进程不响应时，下一轮执行详细扫描。
脚本错误、求解器错误文件和完成标记仍在每轮检查。新增模态窗口的详细检测可能延迟至下一次扫描。

8.40 实机的 `RedirectMessages` 会独占消息文件。官方 `RedirectMessages flush` 可以将缓冲内容
写入磁盘，但不会释放文件的独占访问。状态查询会刷新日志，确保异常结束时已写出的错误内容得到保留。
遇到文件暂不可读时，监控继续保留原超时控制；任务进程退出后重新读取日志，补充实际脚本错误。
返回结果保留 `termination_classification`，区分终止时的监控原因与读取日志后确认的错误类别。
这类独占日志中的脚本错误无法保证实时识别。

原有启动、停滞和总时长设置未放宽。该修改没有证明其他用户报告的 SIMetrix 界面挂起已经修复。
